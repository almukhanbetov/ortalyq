# ORTALYQ — MVP платформы онлайн-занятий

Демонстрационный MVP: поиск преподавателя → запись на занятие → видеокласс (LiveKit) → общая доска (Excalidraw) и совместный редактор кода с запуском Python (Monaco + Yjs, исполнитель Judge0 на отдельном сервере) → запись урока (LiveKit Egress → S3) → домашнее задание → отзыв.

Стек: **Go 1.26 + Gin**, **PostgreSQL 17**, **Next.js 15 + TypeScript + Tailwind**, **LiveKit** (видео и запись), **S3-совместимое хранилище** (в compose — RustFS), **Caddy** (HTTPS).

```
backend/    Go API: авторизация, роли, расписание, файлы, WebSocket доски и чата, запись
frontend/   Next.js: каталог, объявления, кабинеты, видеокласс, шаблон записи /recorder
deploy/     Caddyfile, Kubernetes (k8s/), Nginx, сервер выполнения кода (code-runner/)
e2e/        сквозной тест занятия в двух браузерах (Playwright)
scripts/    запуск бэкенда в dev-режиме, проверка API
docs/       план и сценарий демонстрации
```

## Быстрый старт (Linux, Docker)

```bash
cp .env.example .env
# заполните секреты (пример генерации: openssl rand -hex 32):
#   POSTGRES_PASSWORD, APP_SECRET, DEMO_PASSWORD,
#   LIVEKIT_API_KEY, LIVEKIT_API_SECRET, S3_ACCESS_KEY, S3_SECRET_KEY
# для Docker-режима оставьте LIVEKIT_PUBLIC_URL пустым

docker compose up -d --build
docker compose exec backend server seed          # демо-данные (миграции применяются автоматически)
```

Откройте **https://localhost:8443**. Сертификат выпускает Caddy (собственный CA), поэтому браузер покажет предупреждение — для локальной демонстрации его можно принять.

> LiveKit и Egress запущены в сети хоста (`network_mode: host`), поэтому compose рассчитан на Linux. На macOS/Windows используйте LiveKit Cloud (см. ниже).

### Демонстрация с двух устройств (компьютер + телефон в одной Wi‑Fi сети)

Камера и микрофон в браузере доступны только по HTTPS, поэтому телефон подключается через Caddy:

1. Узнайте IP компьютера в локальной сети (`ip -4 addr`), например `192.168.1.10`.
2. В `.env`:
   ```
   LIVEKIT_NODE_IP=192.168.1.10
   SITE_ADDRESSES=https://localhost:8443, https://192.168.1.10:8443
   PUBLIC_ORIGINS=https://localhost:8443,https://192.168.1.10:8443,http://localhost:13000
   ```
3. `docker compose up -d` и откройте на телефоне `https://192.168.1.10:8443` (примите предупреждение о сертификате).
4. Откройте в файрволе порты **8443/tcp**, **7881/tcp** и **7882/udp** (медиа LiveKit идёт напрямую по UDP 7882, при блокировке — по TCP 7881).

Если устройства в разных сетях, нужен публичный сервер с доменом или LiveKit Cloud. Запуск в production этим README не покрывается.

## Демо-аккаунты

Демо-данные адаптированы под Казахстан: суммы в тенге (**₸**, целые тенге, формат «5 000 ₸»), казахстанские имена, города Алматы, Астана, Шымкент и Караганда, часовой пояс по умолчанию **Asia/Almaty** (в БД время хранится в UTC). Телефоны демо-пользователей вида `+7 700 000 00 XX` — вымышленные.

`seed` пересоздаёт вымышленные данные. Все имена и объявления помечены «(ДЕМО)», пароль всех демо-аккаунтов — значение `DEMO_PASSWORD` из `.env`.

| Роль | Email |
|---|---|
| Преподаватель | `teacher@demo.ortalyq.local` |
| Ученик | `student@demo.ortalyq.local` |
| Второй ученик (для проверки отсутствия доступа к чужому занятию) | `student2@demo.ortalyq.local` |

### Как войти в виртуальный класс

1. Откройте **https://localhost:8443/login** и войдите как преподаватель (на втором устройстве или в окне инкогнито — как ученик).
2. Откроется **Кабинет** (`/dashboard`). Вверху — блок **«Виртуальный класс открыт»** с кнопкой **«🎥 Войти в класс»**; то же занятие есть в разделе **«Мои занятия»** (и в меню «Мои занятия» → `/lessons`).
3. Проверьте камеру и микрофон → **«Войти в класс»**. Второй участник делает то же со своего аккаунта и попадает в ту же комнату.

**Демо-класс** (`always_open`) открыт в любое время — ждать начала не нужно, фоновые задачи его не отменяют. Если класс завершили или доска заполнена, пересоздайте только его:

```bash
docker compose exec backend server demo-room
```

Уже существующую базу можно обновить под Казахстан без удаления пользователей, занятий, файлов и записей (меняются только демо-записи, команду можно запускать повторно):

```bash
docker compose exec backend server localize-demo
```

Обычные занятия открываются за 15 минут до начала (`JOIN_EARLY_MINUTES`). `seed` также создаёт будущие и завершённые занятия: доска, чат, проверенное домашнее задание, отзыв.

Если LiveKit не настроен, класс всё равно открывается: доска и чат работают, а видео, камера, микрофон, экран и запись помечены как недоступные с указанием причины.

Администратор демо-данными не создаётся. Создайте его с собственным паролем:

```bash
docker compose exec -e ADMIN_PASSWORD='длинный-пароль' backend server create-admin -email admin@example.com
```

## Режим разработки

```bash
docker compose up -d postgres rustfs redis livekit egress
# в .env: LIVEKIT_PUBLIC_URL=ws://localhost:7880 (браузер на этом же компьютере)
./scripts/dev-backend.sh migrate        # миграции
./scripts/dev-backend.sh seed           # демо-данные
./scripts/dev-backend.sh                # API на :18080
cd frontend && npm ci && npm run dev    # http://localhost:13000, /api проксируется на :18080
```

Команды бэкенда: `serve`, `migrate`, `seed`, `create-admin`. Миграции — SQL-файлы в `backend/internal/db/migrations`; они применяются по порядку, учитываются в таблице `schema_migrations`, а advisory lock защищает от параллельного запуска.

Для записи шаблон `/recorder/...` должен быть доступен сервису Egress по `RECORDING_TEMPLATE_BASE_URL` (`http://127.0.0.1:13000`). Поэтому в dev-режиме фронтенд нужно запускать на порту 13000.

## Настройка внешних сервисов

### Видео (LiveKit)

| Вариант | Что указать |
|---|---|
| Self-hosted (compose) | `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` (секрет ≥ 32 символов), `LIVEKIT_NODE_IP`. Бэкенд обращается к `http://host.docker.internal:7880`, браузер — к `wss://<сайт>/rtc` через Caddy |
| LiveKit Cloud | `LIVEKIT_URL=https://<project>.livekit.cloud`, `LIVEKIT_PUBLIC_URL=wss://<project>.livekit.cloud` и ключи проекта. Сервисы `livekit`/`egress` из compose не нужны |

Без ключей сайт работает, но вход в класс показывает сообщение «Видеосвязь не настроена».

Токен комнаты выдаёт только бэкенд (`POST /api/lessons/:id/join`): только участнику занятия, только в окне от начала минус 15 минут до конца плюс 60 минут, и только в комнату этого занятия.

### Запись (LiveKit Egress)

- Используется **RoomComposite Egress** с собственным шаблоном `frontend/src/app/(bare)/recorder`. Headless Chrome сервиса Egress открывает страницу, на которой нарисованы **доска** (или **демонстрация экрана**, если она идёт, тогда доска уменьшается в боковой колонке), камеры участников и их **звук**.
- MP4 (H.264 + AAC) Egress загружает **напрямую в закрытый S3-бакет**: `lessons/<id>/recordings/<id>.mp4`.
- Перед стартом нужно согласие обоих участников. Преподаватель подтверждает его при запросе, ученик — в диалоге. Без согласия запись не начинается; запрос истекает через 3 минуты.
- Статусы: ожидает согласия → запускается → **идёт запись** → **обрабатывается** → **готова** / **ошибка**. Статус обновляется по вебхуку LiveKit и дополнительно опросом Egress.
- Переменные: `RECORDING_ENABLED=true`, `RECORDING_TEMPLATE_BASE_URL`, `EGRESS_S3_ENDPOINT` (адрес S3, доступный контейнеру Egress).
- Egress — отдельный сервис (образ около 1,5 ГБ, нужен `SYS_ADMIN`, требовательный к CPU: примерно 2 ядра на одну запись 720p). В LiveKit Cloud Egress тарифицируется отдельно, а S3 должен быть доступен из интернета (например, AWS S3 или Cloudflare R2).
- Если запись не настроена, кнопка неактивна и показывает точную причину.

### Хранилище (S3)

`S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_BUCKET`, `S3_USE_SSL`, `S3_REGION` подходят для любого S3-совместимого хранилища. Бакет создаётся без публичной политики. Файлы выдаются только через временные ссылки бэкенда (`/api/files/<HMAC-токен>`, срок 10 минут, поддерживается Range для перемотки видео). Ссылку получает только участник занятия после проверки прав.

Ограничения загрузки: до `MAX_UPLOAD_MB` (по умолчанию 20 МБ); типы PDF, DOC(X), XLS(X), PPT(X), TXT, MD, PNG, JPG, WEBP, MP3. Содержимое файла сверяется с расширением.

## Проверки

```bash
set -a; source .env; set +a
./scripts/api-check.sh                                  # 37 проверок API (права, двойное бронирование, ДЗ…)
cd e2e && npm ci && BASE=https://localhost:8443 node lesson-flow.mjs   # 19 шагов в двух браузерах
BASE=https://localhost:8443 node classroom-entry.mjs                    # вход из кабинетов, доска и чат (NOVIDEO=1 — без LiveKit)
BASE=https://localhost:8443 node code-editor.mjs                        # вкладка «Код»: синхронизация, запуск, права, телефон
```

`code-editor.mjs`: `RUNNER=none` — бэкенд без исполнителя (проверяется «Сервис выполнения не настроен»), `RUNNER=stub` или реальный Judge0 — проверяются запуски.

`api-check.sh` и e2e изменяют демо-данные: после них выполните `seed`. Для e2e нужен Google Chrome (`CHROME=/путь`) и Docker (для ffprobe).

## Развёртывание на сервере (Kubernetes, CI/CD)

GitHub Actions:
- `CI` — тесты Go с PostgreSQL, проверка TypeScript, сборка Next.js;
- `Images` — образы в GHCR с тегом SHA коммита;
- `Deploy` — только ручной запуск.

Манифесты Kubernetes лежат в `deploy/k8s`, конфигурации Nginx для поддоменов — в `deploy/nginx`. Пошаговая настройка VPS, секретов, сертификатов, а также процедуры отката и восстановления — в [docs/DEPLOY.md](docs/DEPLOY.md).

## Редактор кода

Вкладка «Код» в классе: общий для преподавателя и ученика код Python 3 и входные данные, запуск и результат у обоих. Код выполняется только на **отдельном** изолированном сервере Judge0 — бэкенд пользовательский код не исполняет. Без настроенного исполнителя редактирование работает, а запуск показывает «Сервис выполнения не настроен». Установка исполнителя, механизмы изоляции и проверка — [docs/CODE_RUNNER.md](docs/CODE_RUNNER.md).

## Безопасность (кратко)

- Пароли хешируются argon2id. Сессия — случайный токен в HttpOnly-cookie (SameSite=Lax), в БД хранится только SHA-256 токена. Попытки входа ограничены по частоте.
- CSRF: изменяющие запросы принимаются только с разрешённых `Origin` (`PUBLIC_ORIGINS`) или с того же хоста.
- Права проверяются на сервере в каждом обработчике. Постороннему пользователю занятие, комната, доска, чат, материалы и записи отвечают 404.
- Двойное бронирование исключено ограничениями `EXCLUDE USING gist` в PostgreSQL (для преподавателя и для ученика), поэтому защита работает и при одновременных запросах.
- Секреты хранятся только в переменных окружения; `.env` в `.gitignore`.
