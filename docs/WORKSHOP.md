# Учебная мастерская

Вкладка «Учебная мастерская» в виртуальном классе. Она даёт:

- общий учебный текст, который преподаватель и ученик редактируют одновременно;
- разбор выделенного фрагмента с помощью ИИ;
- домашнее задание по тексту и опубликованным разборам.

Результаты ИИ — **рекомендации**. Преподаватель проверяет и при необходимости исправляет их. Только после этого он показывает их ученику. ИИ не ставит оценок.

## Режимы

| Режим | Действия |
|---|---|
| **Общий** — любой предмет, учитывается название предмета урока | «Объяснить», «Проверить ответ», «Создать упражнения» |
| **Английский** | «Исправить и объяснить» (грамматика и словоупотребление; объяснение на русском; естественный вариант; примеры; короткие упражнения) и действия общего режима |

- Режим выбирает преподаватель. Выбор сохраняется для урока.
- Функциональность не зависит от названия предмета. Название влияет только на подсказку «Для этого предмета есть режим …».
- Сложность («проще», «стандартно», «сложнее») задаётся для каждого запроса.
- «Проверить ответ» выдаёт вердикт: верно, допустимый вариант, ошибка или не хватает условия. Если исходных данных недостаточно, модель должна прямо написать об этом.
- Произношение не оценивается. Аудио и распознавание речи в этот этап не входят.

**Как добавить режим** (например, математику). Добавьте значение `Mode` в `backend/internal/workshop/modes.go`: действия, указания для модели и, по желанию, подсказку по названию предмета. API, таблицы, права и интерфейс общие, менять их не нужно. Неготовые режимы в список не добавляйте: интерфейс показывает все режимы из этого списка.

## Как устроено

```
frontend/src/components/workshop/   WorkshopPanel (вкладка класса), Materials (разборы и задания), LessonWorkshop (страница урока)
frontend/src/lib/yjsSync.ts         синхронизация документа Yjs (общая с редактором кода, префикс сообщений свой)
backend/internal/realtime/code.go   журнал Yjs: code_docs (код) и workshop_docs (учебный текст) — разные документы
backend/internal/api/workshop.go    HTTP API и проверки прав
backend/internal/workshop/          режимы, структура результатов, промпты, провайдер OpenAI
backend/internal/db/migrations/0005_workshop.sql
```

**Учебный текст** — отдельный документ Yjs. У него своя таблица `workshop_docs` и свои сообщения `workshop.*` в WebSocket урока. С редактором кода он не смешивается.

Механизм тот же, что у редактора кода:
- сервер нумерует бинарные обновления, сохраняет их и рассылает другим участникам;
- одновременные правки сливаются без потерь;
- после перезагрузки страницы текст восстанавливается.

Правки отклоняются сервером в двух случаях:
- урок завершён или отменён;
- истекло окно класса (время окончания урока по расписанию).

**Хранение.** Таблицы:

| Таблица | Что хранит |
|---|---|
| `workshop_settings` | режим и подтверждение передачи текста ИИ |
| `workshop_analyses` | исходный фрагмент, действие, сложность, `draft` (рекомендация, правки преподавателя), `published` (версия для ученика) |
| `workshop_homework` | `draft` (повторение и 5 упражнений), `answer_key` (ответы и советы по проверке), `published` |

Миграция только добавляет таблицы. Предыдущая версия приложения работает на обновлённой базе.

## Права (проверяются на сервере)

| Действие | Кто может | Когда |
|---|---|---|
| Видеть мастерскую и текст | участники урока (посторонним — 404) | всегда, в том числе после урока |
| Править учебный текст | оба участника | пока открыт класс |
| Режим, запросы к ИИ | преподаватель этого урока | пока открыт класс |
| Правка, «Показать ученику», «Опубликовать», снятие, удаление | преподаватель этого урока | пока урок не отменён (после завершения — можно) |

Ученик получает **только опубликованные** версии:
- Для ученика сервер использует отдельные структуры без полей черновика и ответов. Эти поля для него даже не читаются из БД.
- По WebSocket рассылается только `{"type":"workshop.changed"}` без содержимого. После этого каждый клиент запрашивает данные по HTTP, а сервер отдаёт их по роли.
- Ответы к домашнему заданию (`answer_key`) ученику не отдаются никогда, в том числе после публикации.

Опубликованные материалы и учебный текст (только чтение) доступны участникам на странице урока после его окончания.

## ИИ (OpenAI)

Используется OpenAI Responses API: `POST /v1/responses` с Structured Outputs (`text.format` = `json_schema`, `strict: true`) и `store: false`.

| Переменная | Назначение |
|---|---|
| `OPENAI_API_KEY` | ключ (только сервер) |
| `OPENAI_MODEL` | модель, обязательно |
| `OPENAI_REASONING_EFFORT` | необязательно, для моделей с рассуждением |
| `OPENAI_TIMEOUT_SECONDS` | по умолчанию 60, максимум 100 |
| `OPENAI_MAX_OUTPUT_TOKENS` | по умолчанию 4000 |
| `WORKSHOP_AI_PER_MINUTE` | по умолчанию 6 на преподавателя |
| `WORKSHOP_AI_PER_HOUR` | по умолчанию 40 на урок |

Без ключа или модели текст, разборы и задания работают. Кнопки ИИ при этом неактивны и показывают причину. Фиктивных ответов нет.

Меры защиты:
- **Запросы только по кнопке преподавателя.** При наборе текста запросов нет.
- **Предупреждение.** Перед первым запросом урока преподаватель подтверждает, что выбранный текст передаётся внешнему ИИ.
- **Минимум данных.** Передаются только предмет урока, выделенный фрагмент, а для задания — текст и опубликованные разборы. Имена, email и другие данные участников не передаются.
- **Текст — данные, а не инструкции.** Текст передаётся во входных данных как JSON, отдельно от инструкций. Модели прямо указано не выполнять команды из текста.
- **Ограничения.**
  - фрагмент — до 4000 символов, текст для задания — до 12 000;
  - длина ответа ограничена;
  - частота: в минуту и в час;
  - один запрос на урок одновременно (повторное нажатие → 409);
  - таймаут.
- **Проверка ответа.** Ответ проверяется по схеме: неизвестные поля, пустые разделы и неверное число упражнений отклоняются. Затем он очищается от управляющих символов. В интерфейсе он выводится только как текст, HTML не исполняется.
- **Ошибки — понятные сообщения:** таймаут, перегрузка, лимит, ключ, отказ модели, некорректный ответ. Тело ответа провайдера и ключ не показываются.
- **Журнал.** Пишутся только урок, вид запроса, категория ошибки и время. Ключ, учебный текст и ответы в журнал не попадают.

## Проверки

```bash
# Go: юнит-тесты провайдера (локальный httptest-сервер) и интеграционные тесты API/WebSocket (TEST_DATABASE_URL)
cd backend && go test ./internal/workshop/ ./internal/api/ -run 'Workshop|OpenAI|Provider|Verdict|Prompts'

# Два браузера. Бэкенд запущен с поддельным провайдером:
#   OPENAI_BASE_URL=http://127.0.0.1:18191/v1 OPENAI_API_KEY=sk-fake-e2e-key OPENAI_MODEL=fake
#   OPENAI_TIMEOUT_SECONDS=5 WORKSHOP_AI_PER_MINUTE=20
cd e2e && PORT=18191 node fake-openai.mjs &
BASE=http://localhost:13000 DEMO_PASSWORD=... node workshop.mjs     # затем: server demo-room
```

`fake-openai.mjs` — только для тестов. Это сервер в формате Responses API с фиксированными образцами ответов. Он проверяет путь адаптера, но не качество ИИ.

С реальным провайдером нужно отдельно проверить:
- формат ответов выбранной модели;
- качество разборов и заданий;
- реальные задержки, лимиты и сообщения об ошибках.
